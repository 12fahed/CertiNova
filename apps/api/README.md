# apps/api

Flask API and RQ worker for CertiNova. Hasura calls the API for each action. The API never gets calls from the browser.

## Layout

| Path | Contents |
|---|---|
| `hasura/` | Action endpoint `/actions/<name>`: secret check, payload parsing, error shape, handler registry |
| `actions/` | One module per area: `orgs`, `batches`, `verify`, `legacy`. Each exports `ACTIONS` |
| `services/` | Storage, job queue, mailer, access checks, legacy decrypt, emails, paths |
| `rendering/` | Template snapshot, text fit, fonts, Pillow renderer. Spec: `docs/revamp/rendering.md` |
| `worker/` | RQ tasks: render, export, email. `python -m certinova_api.worker` |
| `db/models.py` | Generated by `npm run db:codegen`. Do not edit |

To add an action:

1. Define it in `hasura/metadata/actions.*`.
2. Write the input model and the handler in the right module under `actions/`.
3. Add it to that module's `ACTIONS` list.
4. Add tests in `tests/integration/`.

A handler that queues work registers the enqueue with `ctx.after_commit(...)`, so the worker never sees a job before its row is committed.

## Run locally

Start the local stack first (see `supabase/README.md` and `hasura/README.md`), then:

```bash
docker run -d --name certinova-redis -p 6379:6379 redis:7.4-alpine
cp apps/api/.env.example apps/api/.env   # set SUPABASE_SERVICE_ROLE_KEY from `npm run supabase -- status`
cd apps/api
uv run flask --app 'certinova_api:create_app()' run --port 5000
uv run python -m certinova_api.worker   # in a second terminal
```

Local Hasura calls `ACTION_BASE_URL` (default `http://host.docker.internal:5000`). If your Docker setup cannot reach the host, run the API image on the Supabase network and start Hasura with `ACTION_BASE_URL=http://certinova-api:5000`.

## Tests

```bash
cd apps/api
uv run pytest                                  # unit tests
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres \
SUPABASE_SECRET_KEY=<from supabase status> \
uv run pytest -W error --cov                   # unit + integration, coverage gate 85%
```

The legacy decrypt test uses `tests/fixtures/legacy_blob.json`, made by the real `certinova-backend/src/utils/crypto.js`.

## Deploy on Render

Build one image from the repo root with `apps/api/Dockerfile`. Use it for two services:

| Service | Type | Start command |
|---|---|---|
| `certinova-api` | Web service | image default (gunicorn on `$PORT`) |
| `certinova-worker` | Background worker | `python -m certinova_api.worker` |

Both services use the env group from `docs/revamp/secrets.md`. Set `APP_ENV=staging` or `prod` there: the app then refuses to start with local default secrets.
